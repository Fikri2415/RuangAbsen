# Menyiapkan absensi bersama dengan MySQL

Versi ini memakai PHP + MySQL. Jangan masukkan kredensial MySQL ke HTML; koneksi database hanya dilakukan server PHP.

## Persiapan hosting

Hosting harus mendukung PHP 8.1 atau lebih baru, ekstensi `PDO_MYSQL` dan OpenSSL, database MySQL 8/MariaDB, serta HTTPS. Buka situs lewat alamat hosting, bukan dengan membuka `index.html` sebagai file lokal.

## Setup database dan API

1. Buat database MySQL dan user database melalui panel hosting. Beri user hak akses pada database tersebut.
2. Untuk pemasangan baru, di phpMyAdmin pilih database dari panel hosting, lalu impor `database.sql`. File ini membuat tabel dan menambahkan empat akun peserta serta satu akun admin. File sengaja tidak membuat atau memilih database karena hosting bersama seperti InfinityFree memakai nama database berawalan prefix dan biasanya melarang `CREATE DATABASE`.
   - Jika aplikasi sudah memakai database lama, jangan impor ulang `database.sql` karena data akun awal dapat diubah. Jalankan satu kali setiap migrasi yang belum pernah diterapkan, termasuk `database-migration-admin-divisions.sql` untuk role admin dan akun administrator, `database-migration-reminder-email.sql` untuk log pengiriman pengingat email, serta `database-migration-announcements-activities.sql` untuk tabel pengumuman dan log aktivitas.
3. Isi `DB_HOST`, `DB_NAME`, `DB_USER`, dan `DB_PASSWORD` pada `api/config.php`. Gunakan akun database khusus aplikasi dengan hak minimum pada database aplikasi.
4. Unggah `login.html`, `index.html`, `profil.html`, `riwayat.html`, `divisi.html`, folder `image/` (termasuk `logo-kesbang.png`), folder `api/`, serta `vendor/` ke hosting. Saat memperbarui API, unggah file terbaru tetapi jangan menimpa `api/config.php` atau `api/reminder-config.php` yang berisi konfigurasi privat. File SQL hanya perlu diimpor melalui phpMyAdmin. Jangan mengunggah file `.env` atau folder `node_modules`.
5. SQL menyiapkan empat akun peserta dan satu akun admin beserta hash kata sandinya. Untuk mengganti atau membuat akun, pengelola dapat menjalankan `php api/create-user.php` dari terminal server; ikuti prompt dan gunakan kata sandi sementara yang kuat minimal 12 karakter. Skrip CLI tidak dapat dijalankan melalui browser.
6. Peserta masuk di situs memakai email masing-masing. Menu **Profil** membuka halaman khusus untuk mengelola data peserta dan memilih divisi. Beranda menampilkan kalender kehadiran bulanan pribadi, pengumuman untuk divisi yang dipilih, dan form log aktivitas harian (satu catatan per tanggal; catatan dapat diperbarui). Menu **Riwayat absensi** menyediakan filter bulan, unduh CSV yang dapat dibuka di Excel, dan cetak laporan atau simpan sebagai PDF melalui dialog cetak browser. Akun admin mendapat panel khusus tanpa tombol absensi harian, dengan menu **Kelola divisi** dan **Kelola riwayat absensi**. Di panel divisi admin dapat membuat, mengubah, dan menghapus pengumuman untuk satu divisi; di riwayat admin dapat melihat semua log aktivitas peserta. API membatasi pengelolaan pengumuman untuk admin, memfilter pengumuman berdasarkan divisi peserta, dan hanya memberi admin akses ke log semua peserta.
7. Pengingat browser di beranda perlu diaktifkan oleh peserta dan hanya berjalan saat halaman beranda terbuka. Untuk email otomatis, salin `api/reminder-config.example.php` menjadi `api/reminder-config.php` di server, isi konfigurasi SMTP dari penyedia email (jangan kirim password SMTP lewat chat), lalu pasang Composer dependencies dengan `composer install` jika folder `vendor/` belum tersedia. Atur cron hosting untuk menjalankan `php /path/ke/aplikasi/api/send-reminders.php` setiap menit pada hari kerja. Skrip mengirim pengingat absen pulang mulai 15.45 WIB dan pengingat absensi belum lengkap mulai 16.15 WIB, paling banyak sekali untuk tiap jenis per peserta per hari.
8. Akun administrator awal adalah `admin@kesbangpol.bandung.go.id`. Setelah mengimpor `database-migration-admin-divisions.sql` (database lama) atau `database.sql` (pemasangan baru), ganti kata sandi sementara sesegera mungkin: jalankan `php api/create-user.php` di server dengan email admin yang sama dan kata sandi baru minimal 12 karakter. Skrip akan memperbarui hash kata sandi tanpa menurunkan role admin. Hanya role `admin` yang dapat membuka halaman Kelola divisi; API juga memeriksa role ini pada setiap perubahan.

Absensi masuk/pulang dan keterangan Tidak hadir/Sakit dicatat oleh server dalam zona waktu WIB. Peserta hanya dapat mengirim satu catatan per hari; keterangan tambahan akan terlihat di halaman riwayat bersama dan pada CSV. Database membatasi satu catatan per anggota per hari. Kata sandi disimpan sebagai hash, dan sesi login memakai cookie HttpOnly serta token CSRF.

Jika saat menyimpan keterangan muncul pesan **“Aksi tidak ditemukan”**, `api/index.php` di hosting masih versi lama. Unggah file `api/index.php` terbaru dari folder proyek (jangan ganti `api/config.php`), lalu impor migrasi database yang belum diterapkan satu kali ke database aplikasi yang sudah ada.

Jika layar login menyebut tabel belum ditemukan, pastikan `database.sql` diimpor ke database yang sama dengan `DB_NAME` pada `api/config.php`. Jika pesannya menyebut akses ditolak, cocokkan empat nilai konfigurasi dengan panel hosting. Detail teknis tersedia di PHP error log; rahasia database tidak ditampilkan kepada pengunjung.

Riwayat lama yang tersimpan di localStorage browser tidak otomatis dipindahkan ke database. Jika kredensial MySQL pernah diletakkan pada berkas yang dapat diakses publik, segera ganti kata sandi database melalui panel hosting. Mengimpor ulang SQL akan menyetel ulang kata sandi untuk empat akun awal.
